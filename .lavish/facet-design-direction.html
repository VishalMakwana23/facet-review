02 · Facet versus observed Lavish UI

Different design philosophy.

The Lavish side reflects the installed local interface we reviewed. The goal is not to restyle Lavish; it is to design a product whose hierarchy and interactions are fundamentally more focused.

04 · Interaction principles

“Best UI” must be measurable.

We should judge the design by task performance, accessibility, and review quality—not by how dramatic the screenshots look.

One dominant surfaceThe artifact canvas always wins the visual hierarchy. Chrome supports orientation and actions.
Mode clarityExplore interacts, Review annotates, Decide commits structured input. No ambiguous clicks.
Context stays attachedComments anchor to semantic elements and versions, with visible orphan or stale states.
Keyboard and pointer parityEvery action is discoverable in menus and fast through shortcuts; focus remains visible.
Progressive disclosureSecondary controls, history, and metadata appear when requested, not all at once.
Human status languageNever expose polling or transport mechanics as the primary user message.
Accessible by construction4.5:1 text contrast, semantic controls, reduced motion, 24px web targets minimum, 44px mobile targets.
Performance is visual qualityInstant selection feedback, stable geometry, no layout jumps, and virtualization for dense artifacts.
05 · Reference products

Borrow principles, not pixels.

These official sources explain the patterns worth learning from. Facet needs its own component geometry, tokens, and workflows.

L
Linear · calmer interface

Takeaway: information-dense tools work when navigation recedes and the main work surface earns the strongest visual weight.

F
Figma · contextual comments

Takeaway: canvas pins, a comment mode, a manageable side rail, resolution, sorting, and filtering keep feedback attached to context.

R
Raycast · search and action model

Takeaway: one-keystroke access, a universal action panel, and consistent extension components make complex functionality feel coherent.

N
Notion · sidebar and editor

Takeaway: an expandable navigation layer can coexist with a spacious editor whose controls fade behind the act of reading and writing.

Especially relevant technical precedent

Raycast’s extension architecture describes a structured JSON render tree, a consistent host component library, and JSON Patch updates. That independently validates the core Facet idea: agents or extensions describe intent, while the host owns a polished, coherent UI.

06 · Avoid list

What will make Facet look cheap.

These are hard constraints for the future design system.

Over-themed chrome

No gold-on-black identity, ornamental serif headings, heavy gradients, or branding that competes with content.

Card soup

Not every paragraph needs a rounded rectangle. Use sections, dividers, alignment, and whitespace first.

Permanent sidebars

Both navigation and review rails must collapse. Focus mode should show only the artifact.

Ambiguous annotation

Users must never wonder whether a click activates the artifact or leaves a comment.

Technical runtime copy

Do not tell users that an agent is polling or listening. Show actionable product states instead.

Animation as decoration

Motion must explain state or spatial continuity; it must remain interruptible and respect reduced motion.
