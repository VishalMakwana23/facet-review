Working codename · proposal, not implementation

A token-efficient canvas for human–agent collaboration.

Facet is a proposed local-first alternative to Lavish: agents emit a compact semantic artifact, a deterministic renderer creates the modern interface, and humans review, decide, annotate, and iterate without regenerating an entire HTML page.

01 · Product thesis

Keep the creativity. Remove the repeated markup.

HTML is a powerful final format, but it is an expensive language for an agent to author repeatedly. Facet makes the model describe intent while software handles pixels, layout, accessibility, and responsive behavior.

Core user

AI-assisted builders

Developers, product teams, researchers, and operators reviewing complex agent output.

Job to be done

Understand and decide

Turn complex reasoning into a surface where a person can inspect, compare, and act.

Unique advantage

Semantic protocol

A small artifact spec renders into consistent, polished, interactive components.

North star

Decision time

Reduce time from agent output to an accepted, clearly recorded human decision.

◈
Scope assumption: start as an open, developer-first local CLI and web UI. Hosted collaboration is an optional later layer, not an MVP dependency.

04 · Architecture

Compact input, deterministic output, durable feedback.

A local daemon coordinates a typed artifact graph, a sandboxed renderer, and an append-only event store. Hosted services remain replaceable adapters.

Protocol package

Typed artifact graph

Versioned schema, stable IDs, reusable definitions, provenance, capability negotiation, and patch operations.

Renderer package

Accessible components

Modern responsive layouts, theme tokens, virtualized dense views, keyboard navigation, print and offline modes.

Runtime package

Event-driven sessions

Durable event inbox, WebSocket/SSE transport, comments, decisions, attachments, presence, and reconnect.

05 · Product experience

A full review workspace, not a decorative page.

The canvas should feel like a modern design-review tool while preserving the simplicity of opening one local artifact.

Canvas

Adaptive artifact view

Document, board, comparison, timeline, data table, diagram, code diff, slide, and dashboard compositions.

Review

Anchored conversations

Element, region, text-range, code-line, data-cell, and freeform pin comments with resolved state.

Decisions

Structured input

Choice, ranking, approval, scope, risk acceptance, form, and checklist blocks that emit typed feedback.

History

Semantic diffs

See which nodes, claims, metrics, and decisions changed—not a wall of raw HTML differences.

Trust

Provenance & citations

Attach source references and confidence to any node, then inspect evidence without leaving the review.

Extend

Capability plugins

Register safe renderer components, exporters, data sources, and agent adapters through versioned manifests.

06 · MVP boundary

Ship the smallest product that proves the thesis.

“Full functionality” is the destination. The MVP must first prove token savings, review quality, and reliable agent feedback without hiding behind hosted collaboration.

MVP must include
  1. Versioned compact artifact schema with 12–15 high-value components.
  2. Local CLI/daemon and responsive browser review canvas.
  3. Stable element and text-range annotations.
  4. Typed choice/approval forms and durable feedback inbox.
  5. JSON Patch revisions with visual semantic diff.
  6. Self-contained offline HTML export.
  7. Threat model, sandbox, CSP, asset size limits, and audit log.
  8. Benchmark harness comparing tokens, latency, defects, and review completion.
Explicitly defer
  • →Real-time multi-user presence and simultaneous editing.
  • →Public cloud hosting, billing, organizations, and enterprise SSO.
  • →Unrestricted third-party JavaScript components.
  • →Native mobile apps; responsive web is sufficient first.
  • →AI-generated themes on every artifact; curated tokens come first.
!
Guardrail: do not chase every Lavish feature at launch. Win decisively on token cost, patchability, reliable feedback, and privacy defaults.

08 · Engineering plan

Recommended implementation shape.

Keep protocol and renderer framework-neutral at the boundaries. The implementation may use TypeScript internally, but the wire format and test fixtures must be language-agnostic.

Monorepoprotocol, renderer, runtime, cli, sdk, exporters, benchmarks, and examples.
ProtocolJSON Schema-compatible definitions, semantic IDs, capability negotiation, and RFC 6902-style patch operations.
Local dataSQLite for metadata/events, content-addressed files for blobs, append-only audit stream, explicit migrations.
TransportHTTP for commands and assets; WebSocket or SSE for feedback/events; durable inbox for disconnected agents.
FrontendComponent-based TypeScript UI, accessible primitives, design tokens, virtualization, responsive layouts, and no CDN runtime.
SecurityLoopback binding by default, random session secrets, strict CSP, sandboxed custom content, no arbitrary scripts, size/rate limits.
TestingGolden render snapshots, schema fuzzing, patch property tests, accessibility checks, mobile widths, offline export verification.
CompatibilityVersioned migrations, capability fallback, unknown-node placeholders, and conformance fixtures for third-party SDKs.
09 · Risk register

What can break the thesis.

Risks are ordered by impact, not likelihood. Each requires evidence before expanding scope.

Schema becomes creatively restrictive

Mitigation: escape-hatch “rich block” with sandboxed markup, plugin capabilities, and benchmark quality scoring. Do not make freeform HTML the default.

Token savings are benchmark theater

Mitigation: compare equal content, interactions, accessibility, and visual fidelity; publish corpus and tokenizer settings.

Stable anchors break across patches

Mitigation: immutable semantic IDs, range context hashes, relocation heuristics, and explicit orphan state instead of silent loss.

Plugins recreate browser security problems

Mitigation: declarative component manifests first; permissioned sandbox workers later; signed capabilities and deny-by-default APIs.

Renderer versions change appearance

Mitigation: pin renderer version in each artifact, provide migration preview, and embed runtime for archival exports.

“Full functionality” delays release

Mitigation: hard MVP boundary and phase gates. Collaboration, cloud, and marketplace work start only after the local loop wins.

10 · Success criteria

Definition of a credible MVP.

All six gates must pass before claiming Facet is a better alternative for its chosen users.

Efficiency

Token benchmark

Median ≥70% reduction and p10 ≥40% across the fixed corpus, including initial artifact and two revisions.

Quality

Blind review

Users rate comprehension and visual quality non-inferior to handcrafted HTML at the same content depth.

Reliability

Feedback delivery

No lost submitted feedback across process restart, browser refresh, or agent reconnect in recovery tests.

Accessibility

Keyboard & screen reader

Core review, comment, and decision paths meet WCAG 2.2 AA expectations and pass manual keyboard tests.

Security

Local trust

No network egress in offline mode; hostile artifact fixtures cannot execute arbitrary code or read local files.

Adoption

Repeat usage

Pilot users choose Facet for a second real task and complete a decision without developer assistance.
